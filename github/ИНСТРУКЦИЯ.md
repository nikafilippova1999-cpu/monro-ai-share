# Перенос агента на GitHub Actions — пошагово

Работает при выключенном компьютере, бесплатно, и у каждого запуска есть журнал
с точным временем и текстом ошибки. Всего 5 шагов, примерно 15 минут.

## Шаг 1. Аккаунт

Зайдите на **github.com** → Sign up. Нужны почта и пароль.
Пароль придумайте свой и мне не присылайте — он нигде не понадобится.

## Шаг 2. Создать репозиторий

Кнопка **New repository** (зелёная, слева вверху).

- Repository name: `ping-checker`
- Выберите **Private** — это важно, чтобы посторонние не видели содержимое
- Поставьте галочку **Add a README file**
- Нажмите **Create repository**

## Шаг 3. Положить два файла

В репозитории нажмите **Add file → Create new file**.

**Файл первый.** В поле имени введите ровно:

```
check_pings.py
```

Вставьте туда содержимое файла `check_pings.py` из папки `nika-bot`.
Внизу нажмите **Commit changes**.

**Файл второй.** Снова **Add file → Create new file**. В поле имени введите ровно:

```
.github/workflows/check_pings.yml
```

(GitHub сам превратит это в папки, когда вы напечатаете косые черты.)
Вставьте содержимое файла `workflows/check_pings.yml`. Нажмите **Commit changes**.

## Шаг 4. Спрятать токены

Токены не должны лежать в коде. Откройте:

**Settings** (вкладка сверху) → слева **Secrets and variables** → **Actions** →
кнопка **New repository secret**.

Создайте три секрета — по одному, каждый раз заполняя Name и Secret:

| Name | Secret |
|---|---|
| `CRM_TOKEN` | токен Easy-Mo из файла `.env` |
| `TG_TOKEN` | токен Telegram-бота из файла `.env` |
| `TG_CHAT_ID` | `699380243` |

После сохранения GitHub больше не покажет их значения — это нормально и правильно.

## Шаг 5. Проверить

Вкладка **Actions** сверху → слева выберите «Проверка пингов после запроса
оплаты» → кнопка **Run workflow** → **Run workflow**.

Через 10–18 минут в Telegram придёт отчёт. Если запуск упадёт, придёт сообщение
со ссылкой на журнал — по ней сразу видно, что именно сломалось.

Дальше он будет запускаться сам каждый час в 15 минут.

## Если что-то пойдёт не так

Пришлите мне ссылку на страницу запуска из вкладки **Actions** — в отличие от
прежней схемы, там виден полный журнал, и причина находится за минуты.

## Полезно знать

- **Выключить на время:** Actions → выбрать workflow → `···` → Disable workflow.
- **Поменять частоту:** строка `cron: "15 * * * *"` в файле `check_pings.yml`.
  Например, `"15 6-21 * * *"` — только с 9 до 24 по Москве.
- **Убрать сообщения «всё чисто»:** удалить строку `PING_FORCE_SEND: "1"`.
  Но сначала стоит пожить с ними неделю: молчание не должно быть двусмысленным.
