# Монро Арт — замер доли ИИ и выгрузки из CRM

Скрипты для подсчёта, какую часть переписки с клиентами ведёт ИИ, а какую
менеджеры. Работают с CRM Easy-Mo и шлют отчёты в Telegram.

## Начало работы

```
cp .env.example .env     # и заполнить токены
```

Токены в репозиторий не попадают: `.env`, выгрузки переписки, зарплатные
таблицы и отчёты перечислены в `.gitignore`.

## Правила счёта

Все расчёты берут правила из одного файла — `method.py`. Коротко:

- **граница оформления** — поле заказа «Дата перевода на ведение» (field_id 40);
- **ИИ — ровно двое:** «Артур ИИ» (`sender_type=arthur_ai`) и «Бот»
  (`sender_type=bot`); в CRM на экране они подписаны «Артур Бот» и
  «Геннадий Горин (Бот)»;
- **менеджеры** — все остальные, даже когда человек копирует скрипт бота;
- **роповские учётки не считаются** ни в числитель, ни в знаменатель —
  через них идут рассылки руководителей;
- **окно** — клиенты, пришедшие с 1 августа 2026, когда внедрили ИИ;
- **доля ИИ** = сообщения ИИ / (ИИ + менеджеры), клиентские не в счёт.

Две когорты, которые считаем:

1. **Заказы, перешедшие на ведение в заданный день** — показывает участие
   бота там, где клиент дошёл до покупки.
2. **Все лиды, пришедшие в заданный день** — показывает охват по всему
   потоку, включая тех, кто отвалился.

## Что где лежит

| Файл | Назначение |
|---|---|
| `method.py` | **Правила счёта.** Единственное место, где они заданы |
| `fetch_cache.py` | Выгрузка диалогов отдела за день с кэшем на диск |
| `fetch_all.py` | То же для нескольких отделов подряд |
| `razbor.py` | Обе когорты по одному отделу, с показом каждого шага |
| `itogi_otdely.py` | Обе когорты сразу по всем пяти отделам |
| `sobrat_po_id.py` | Когорта по списку клиентов (когда окно не подходит) |
| `bez_chistogo_bota.py` | То же, но без клиентов, которых бот вёл в одиночку |
| `nagruzka.py` | Сколько диалогов и сообщений приходится на менеджера в смену |
| `show_one.py` | Построчный разбор одного клиента: кто что писал и где граница |
| `ai_share_daily.py` | Ежедневный отчёт по доле ИИ в Telegram |
| `run_ai_share.ps1` | Запуск ежедневного отчёта из планировщика Windows |
| `check_pings.py` | Отдельный агент: кому не ответили 10 минут после запроса оплаты |
| `ЗАПРОСЫ.md` | Какие запросы к CRM нужны и какие у них ограничения |

## Ограничения CRM

- выгрузка диалогов фильтрует по **дате создания клиента**, не по дате сообщений;
- за один запрос — **один день и один отдел**, не больше 100 на страницу;
- поле «Дата перевода на ведение» есть только в заказах, а прямого HTTP-API
  для заказов нет: `/external/v1/orders` отвечает 405, GET отдаёт HTML.
  Поэтому полный расчёт пока делается не автоматически.

Подробности и примеры запросов — в `ЗАПРОСЫ.md`.
